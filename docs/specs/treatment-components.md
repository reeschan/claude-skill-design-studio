# 表現 (面と動き)・部品帳・デザインガイド

## Problem Statement

design-studio で作れるのは、画面 1 枚分のページだけになっている。利用者 (デザイナーでない人) からは、次の不満が出ている。

- ページ全体ではなく、ボタン・カード・モーダルなどの部品の単位で見た目を作りたいのに、その手段がない
- 決めた見た目を、部品の一式や文章の決まりとして持ち出し、ほかの人やほかの道具に渡せない
- 「Material っぽく」「すりガラスの Glass で」「べた塗りの Solid で」「動きのある感じで」と、面の作り方や動きを明示して頼めない。今は配色とフォント (スタイル・方向性) しか指定できず、面や動きは LLM 任せになる
- 動きのある画面を作りたくても、どんな動きが作れるか、どれが今の CSS で美しく動くかが分からない
- 今のページの決まり (色・角丸・影はテーマのユーティリティだけ) では、半透明の面・背景のぼかし・`@keyframes` の動きを書く余地がない

## Solution

スタイル・方向性とは別の軸として **表現** を足し、作れるものを **部品帳**・**部品**・**デザインガイド** まで広げる。

- 表現は **面** (Material / Glass / Solid / 指定しない) と **動き** (なし / 控えめ / Animated) の組。プロジェクトに 1 つ持ち、利用者が明示的に選ぶ。混ぜる対象にはしない (ADR 0004)
- 動きを Animated にすると、同梱の **動きの見本集** (2026 年の CSS で作った 12 件) から 2〜4 件を主役に使う。既定は LLM が選び、利用者が指定することもできる
- 作るものを、ページ・部品帳 (決まった 10 個の部品の一式)・部品 (候補か自由な名前で 1 つ)・デザインガイド から選べる
- デザインガイドは、部品帳・トンマナ・スタイルガイド・テーマを 1 つのフォルダにまとめる。トークンの文書 (`style-guide.md`) は style-guide が作り、トンマナと部品の使い方 (`design-guide.md`) は design-studio が作る (ADR 0005)。style-guide が文書を出せない古い版なら、部品帳だけを作り、更新を案内する
- ページの CSS の決まりを広げ、自分で書く `<style>` で `@keyframes`・`@property`・`backdrop-filter`・`mask` を、ユーティリティで透明度 (`bg-card/60`) と `backdrop-blur-*` を使えるようにする。色はテーマの変数から作るという線は守る
- reduced-motion への対応を必須にし、`check-page` で確かめる
- スキルの手順 (会話の中) と作業台 (アプリ) の両方でできる。見本帳には「表現」のタブを足す

## User Stories

表現を選ぶ

1. 利用者として、面を Material・Glass・Solid・指定しない から選びたい。面の作り方を言葉で説明しなくても伝えられるから
2. 利用者として、動きを なし・控えめ・Animated から選びたい。動きの強さを自分で決められるから
3. 利用者として、面と動きを別々に選びたい (例: Glass × Animated)。面の好みと動きの好みは別だから
4. 利用者として、どのスタイル・方向性にも表現を掛け合わせたい (例: 和モダン × Glass)。配色の好みを変えずに面だけ変えられるから
5. 利用者として、面と動きのそれぞれに短い説明を見たい。選ぶ前にどんな見た目になるかが分かるから
6. 利用者として、何も選ばなければ今までどおりの結果になってほしい。表現を気にしない人の使い方が変わらないから
7. 利用者として、表現を案を出す前に選びたい。表現に合う配色の案が出るから
8. 利用者として、案を出したあとで表現を変えても、案を出し直さずに済んでほしい。数十秒待たずに試せるから
9. 利用者として、表現がパッドで混ざらないでほしい。Glass と Solid の中間のような、意味のない見た目にならないから
10. 利用者として、骨組みのプレビューでも面の違いを見たい。案を見比べる段階で、面との相性を確かめられるから
11. 利用者として、骨組みのプレビューは動かないでほしい。案どうしを同じ条件で落ち着いて見比べられるから
12. 利用者として、プロジェクトを開き直したとき、選んだ表現が残っていてほしい。続きから作業できるから

動き

13. 利用者として、「控えめ」を選んだら、ホバー・押下・開閉の短い動きだけにしてほしい。業務の画面でもうるさくならないから
14. 利用者として、「Animated」を選んだら、見て美しいと感じる動きを主役にしてほしい。印象に残る画面になるから
15. 利用者として、Animated で使える動きの見本を一覧で見たい。どんな動きが作れるかが分かるから
16. 利用者として、動きの見本が実際に動く様子を見たい。名前だけでは動きが想像できないから
17. 利用者として、動きの見本に「どこで使うと良いか」(ボタン・見出し・セクションなど) の説明が欲しい。自分の画面に合うかを判断できるから
18. 利用者として、使いたい動きの見本を指定したい。気に入った動きを必ず入れられるから
19. 利用者として、何も指定しなければ、依頼と画面に合う動きを AI に選んでほしい。動きに詳しくなくても任せられるから
20. 利用者として、動きを減らす設定 (reduced-motion) の人には、動きが止まるか弱まってほしい。誰にとっても使える画面になるから
21. 利用者として、一部のブラウザでしか動かない動きを使ったときも、ほかのブラウザで崩れないでほしい。見る人のブラウザを選ばないから
22. 利用者として、動きの見本がテーマの色で動いてほしい。ページの配色となじむから

作るもの

23. 利用者として、作るものを ページ・部品帳・部品・デザインガイド から選びたい。今欲しいものだけを作れるから
24. 利用者として、部品帳で、ボタン・入力欄・カード・ナビ・タブ・バッジ・モーダル・トースト・表・料金カードを 1 枚で見たい。見た目の決まりが部品ごとにどう効くかを一度に確かめられるから
25. 利用者として、部品 1 つだけを候補から選んで作りたい。気になる部品だけを作り込めるから
26. 利用者として、候補にない部品を自由な名前 (例: 「予約カレンダー」) で頼みたい。自分の作りたい部品を作れるから
27. 利用者として、部品の状態 (通常・ホバー・押下・フォーカス・無効) を並べて見たい。状態ごとの見た目を確かめられるから
28. 利用者として、部品の大きさの違い (S / M / L) を並べて見たい。使う場所に合う大きさを選べるから
29. 利用者として、部品に実際にホバーしたり押したりして試したい。止まった見本だけでは手触りが分からないから
30. 利用者として、モーダルやトーストを、開いた状態で見たい。スクリプトが無くても見た目を確かめられるから
31. 利用者として、部品帳と部品にも、選んだ表現が効いていてほしい。ページと部品で見た目がそろうから
32. 利用者として、部品帳と部品も、今のページと同じく外へ通信しない安全な HTML であってほしい。書き出したものを安心して使えるから
33. 利用者として、部品帳を作り直しても、前に作った部品が消えないでほしい。気に入ったものを残せるから
34. 利用者として、作るのに失敗したら、理由と再試行の手段を見たい。どうすればよいか分かるから

デザインガイド

35. 利用者として、デザインガイドを選ぶと、部品帳・トンマナ・スタイルガイド・テーマが一度にできてほしい。持ち出す一式をまとめて作れるから
36. 利用者として、トンマナで、口調 (です・ます / くだけた調子)・文体・使う言葉と避ける言葉・ボタンやエラーの文言の例を見たい。文章を書く人がぶれずに書けるから
37. 利用者として、トンマナで、性格を表すキーワードと、表現の使いどころ・避けることを見たい。新しい画面を足す人が見た目をそろえられるから
38. 利用者として、部品ごとの使い方 (用途・状態・使いどころ・してはいけないこと) を文書で読みたい。部品を使う人が迷わないから
39. 利用者として、スタイルガイド (色トークン・フォント・コントラスト) が style-guide の文書と同じ形で入っていてほしい。style-guide を使っている人と同じ文書で話せるから
40. 利用者として、デザインガイドを 1 つのフォルダとして受け取りたい。そのまま人に渡したり、リポジトリに入れたりできるから
41. 利用者として、デザインガイドの文書が、部品帳とスタイルガイドへの参照を持っていてほしい。文書から見本へたどれるから
42. 利用者として、style-guide が古くて文書を作れないときは、部品帳だけでも作ってほしい。作業が止まらないから
43. 利用者として、そのときは「style-guide を更新するとデザインガイドも作れる」と教えてほしい。次に何をすればよいか分かるから
44. 利用者として、作業台の中で、デザインガイドの文書の中身を読みたい。ファイルを開かなくても確かめられるから

保存

45. 利用者として、ページと並べて、部品帳・部品・デザインガイドもプロジェクトに保存したい。作ったものを 1 か所で管理できるから
46. 利用者として、保存した 1 件ごとに、どの表現で作ったかを知りたい。表現を変えたあとでも、昔のものがどの表現かが分かるから
47. 利用者として、前の形で保存したプロジェクトも開きたい。これまでの作業が無駄にならないから

会話の中 (スキル) で使う

48. 利用者として、会話の中でも「Glass で」「Animated で」と表現を指定したい。アプリを開かなくても頼めるから
49. 利用者として、会話の中でも部品帳・部品・デザインガイドを作ってほしい。アプリと同じものを会話で得られるから
50. 利用者として、会話の中で動きの見本の一覧を見たい。どの動きを使うかを会話で選べるから

見本帳

51. 利用者として、見本帳で、面ごとの部品帳を見比べたい。Material・Glass・Solid の違いを同じ条件で見られるから
52. 利用者として、見本帳で、動きの見本が実際に動く一覧を見たい。作る前に動きを選べるから

## Implementation Decisions

表現 (ADR 0004)

- 表現は「面」と「動き」の組で、プロジェクトに 1 つ持つ。面は `material` / `glass` / `solid` / `none` (指定しない) の 4 つ、動きは `none` / `subtle` (控えめ) / `animated` の 3 つ。既定は `none` × `none` で、今までの結果と同じになる
- Animated のときだけ、利用者が指定した動きの見本の id の並び (0〜4 件、任意) を持つ。空なら LLM が 2〜4 件を選ぶ
- 面の台帳と動きの見本集は、リポジトリのデータのファイルに持つ。コードを変えずに面を足せる形にする (Neumorphism・Brutalism などはあとで足す)
- 面の台帳の 1 件は、id・名前・説明・LLM への指示 (その面の作り方の決まり)・骨組みに重ねる CSS の層・使いどころの例を持つ
  - Material: 面の高さを影と色の濃さで表す、状態のレイヤ (ホバー・押下で面の色を少し重ねる)、大きめの角丸
  - Glass: 半透明の面 (テーマの色を `color-mix()` か透明度で薄めたもの) + 背景のぼかし + 縁の光。CSS だけでは屈折は出ないので、SVG フィルタでの歪みは Chromium だけの上乗せとし、`@supports` で無いときの見た目を用意したときだけ使う。ぼかしは重いので、使うのは目立つ面 (ヒーロー・ナビ・モーダル) に絞る
  - Solid: 半透明もグラデーションも使わない。べた塗りと線で面を作る
- 表現は、方向性の案を出す LLM への条件として渡す (表現に合う配色の案にする)。混ぜる軸には入れない。表現を変えても案は出し直さない
- 骨組みには、面の台帳の CSS の層だけを重ねる (テーマの style のあとに別の style として入れる。CSP の meta の位置の決まりは変えない)。動きは骨組みに入れない
- 動きの線引き:
  - なし: 動かさない (フォーカスの表示だけ)
  - 控えめ: ホバー・押下・開閉の短い transition だけ (0.3 秒くらいまで)。ずっと動き続けるもの・スクロールに連動するものは使わない
  - Animated: 動きの見本集から 2〜4 件を主役に使ってよい。ずっと動き続けるもの・スクロールに連動するものも使える

動きの見本集

- 動きの見本の 1 件は、id・名前・説明・使いどころ (ボタン・見出し・セクションなど)・技法・CSS・見本の HTML・対応 (主要ブラウザで Baseline か、Chromium だけで代わりの見た目つきか)・ずっと動くか・スクロール連動か・参考にしたページの URL を持つ
- CSS は、写さずに技法を元に書き直す。色はテーマの CSS 変数だけを使う。どの見本も `prefers-reduced-motion: reduce` のときの扱いを持つ
- 最初の 12 件:

| #   | 名前                         | 技法                                                          | 使いどころ                         |
| --- | ---------------------------- | ------------------------------------------------------------- | ---------------------------------- |
| 1   | 回る光の枠                   | `@property` で角度を登録し、`conic-gradient` の枠を回す       | ボタン・カード                     |
| 2   | 光が流れる文字               | グラデーションを `background-clip: text` で文字に当てて動かす | 見出し                             |
| 3   | スクロールで現れる           | `animation-timeline: view()` + `animation-range`              | セクション・カード                 |
| 4   | 読んだ量のバー               | `animation-timeline: scroll(root)`                            | ブログ                             |
| 5   | 出てくるときの動き           | `@starting-style` + `transition-behavior: allow-discrete`     | モーダル・ポップオーバー・トースト |
| 6   | ばねで押し込む               | `linear()` のイージング                                       | ボタンの押下                       |
| 7   | ずらして出す                 | `sibling-index()` (無いブラウザでは同時に出す)                | 一覧・ベントーグリッド             |
| 8   | ゆっくり流れるオーロラの背景 | 複数の radial-gradient の位置を `@property` で動かす          | ヒーロー                           |
| 9   | 読み込み中のきらめき         | skeleton shimmer                                              | カード                             |
| 10  | 線が描かれていく SVG         | `stroke-dashoffset`                                           | アイコン・図                       |
| 11  | 形が揺らぐ blob              | `border-radius` の変化                                        | 装飾                               |
| 12  | 流れ続ける帯                 | `translate` の無限ループ (marquee)                            | ロゴの帯                           |

- 動きの見本集は、Animated のときに LLM へ参考として渡す (指定された見本は必ず使い、ほかは候補)。作業台と見本帳では、見本ごとに実際に動く見本を見せる

ブラウザの対応

- 主要ブラウザで Baseline の機能は普通に使う
- Chromium だけの機能 (`sibling-index()`・scroll-triggered animations・`corner-shape`・SVG フィルタの屈折) は、`@supports` で無いときの見た目を用意したときだけ使う
- 動き (`@keyframes`・`animation`・`transition`) を使うときは、`prefers-reduced-motion: reduce` のときに止めるか弱める指定を必ず置く

ページの CSS の決まり (page-recipe と共有メモリのページの形を改める)

- テーマの style (`id="theme"`) とは別に、自分で書く `<style>` を置いてよい。そこでは `@keyframes`・`@property`・`backdrop-filter`・`mask` を書いてよい
- 色は、そこでもテーマの CSS 変数か、それを `color-mix()` で薄めたものだけを使う。色の直書き (`#fff`・`bg-blue-500` など) は今までどおりしない
- ユーティリティでは、透明度の付け方 (`bg-card/60` など) と `backdrop-blur-*` を使ってよい
- CSP の meta・外部の読み込み先・インラインのスクリプトを使わないことは変えない

部品帳と部品

- 部品帳は、次の 10 個の部品を 1 枚に並べた 1 ファイルの HTML: ボタン・入力欄 (テキスト・選択・チェック・スイッチ)・カード・ヘッダーのナビ・タブ・バッジ/タグ・モーダル・トースト・表・料金カード
- 部品は、上の 10 個から選ぶか、自由な名前で 1 つを作る 1 ファイルの HTML。自由な名前は、そのまま LLM に渡す
- 部品帳と部品は LLM が作る (ADR 0001 にそろえる。決まった HTML の骨組みは作らない)。ページと同じ殻 (CSP の meta・テーマの style) と `check-page` を通す
- 状態は 2 段で見せる: (1) 状態ごとに並べた止まった見本 (その状態の見た目をクラスで固定したもの)、(2) 実際にホバー・押下・フォーカスできる見本。モーダルとトーストは、開いた状態を枠の中に置いて見せる。大きさの違い (S / M / L) がある部品は並べる
- LLM には、依頼・方向性・表現・面の台帳の指示・(Animated なら) 動きの見本集を渡す。タイムアウトはページと同じ 600 秒、不正な出力のやり直しは 1 回まで

デザインガイド (ADR 0005)

- デザインガイドは、次のファイルを 1 つのフォルダに置いたもの:
  - `style-guide.md`: style-guide が作るトークンの文書。手を加えない
  - `design-guide.md`: design-studio が作る。トンマナ・表現・部品の使い方。`style-guide.md` と部品帳への参照を持つ
  - 部品帳の HTML、`theme.css`、`theme.json`
- `design-guide.md` の章: トンマナ (言葉: 口調・文体・使う言葉・避ける言葉・文言の例 / 見た目: 性格を表すキーワード 3〜5 個・表現の使いどころ・避けること)、表現 (面・動き・使った動きの見本)、部品 (部品ごとの用途・状態・使いどころ・してはいけないこと)、参照
- `design-guide.md` は、LLM に構造化した値 (トンマナ・部品ごとの使い方) を返させ、design-studio が決まった形の Markdown に組み立てる。見出しの形がぶれないようにし、値を検証できるようにするため (設計者の判断。利用者とは未確認)
- デザインガイドを作るときは、部品帳の生成とトンマナ・部品の使い方の生成を並べて走らせてよい
- style-guide に「Seed から文書も出す」口を足す: `render --seed` に文書のオプションを足し、指定したときだけ Seed ごとの `style-guide.md` の中身を返す (`--out` があれば書く)。オプションを付けないときの出力は今と変えない。文書の「推定の出どころ」と「別案」は空にする。中身は今の文書を組み立てる関数をそのまま使う
- style-guide が古い (文書のオプションを知らない) かは、今の `style-guide-outdated` と同じく、`render` が使い方の誤りを返したかで見分ける。そのときは部品帳だけを作り、`design-guide.md` と `style-guide.md` は作らず、「style-guide を更新するとデザインガイドも作れます」と知らせる
- design-studio の台帳が固定している style-guide の ref を、文書のオプションを足した版に上げる

作業台

- 依頼のフォームに、面と動きの選択を足す。動きが Animated のときだけ、動きの見本の一覧 (実際に動く見本つき) を開いて、必ず使うものにチェックを付けられる
- ページを作るボタンの横に「作るもの」(ページ / 部品帳 / 部品 / デザインガイド) を置く。部品のときは、候補の 10 個から選ぶか自由な名前を書く
- 作ったものは中央のプレビューに出す。デザインガイドのときは、部品帳をプレビューに出し、`design-guide.md` と `style-guide.md` の中身を読める場所と、保存先を出す
- サーバーに、表現の一覧 (面の台帳と動きの見本集) を返す API と、作るものを入力に取る生成の API を足す。今のページの API は、表現を省いたら今までどおり動く
- 今の作業台の決まりは引き継ぐ: API の値は `innerHTML` に入れない。プレビューの iframe は `sandbox="allow-scripts"` だけ。古い応答は作業の世代で捨てる

スキルの手順 (会話の中)

- CLI に、表現の一覧を返すサブコマンドを足す (面の台帳と動きの見本集)
- `render-direction` に面のオプションを足し、骨組みに面の CSS の層を重ねる
- CLI に、デザインガイドのフォルダを組み立てるサブコマンドを足す。入力は方向性・表現・部品帳の HTML・トンマナと部品の使い方の値で、style-guide の文書の口を呼んで `style-guide.md`・`theme.css`・`theme.json` を得て、`design-guide.md` を組み立てて書く。style-guide が古ければ部品帳とテーマだけを書き、そのことを出力で知らせる
- page-recipe に、部品帳・部品・デザインガイドの作り方と、広げた CSS の決まりを足す。SKILL.md の段階 (ページの段階) に、作るものの選び方と表現の指定を足す

点検

- `check-page` に動きの点検を足す: HTML に `@keyframes`・`animation`・`transition` (Tailwind の `animate-*`・`transition*` を含む) があるときは、`prefers-reduced-motion` の指定 (CSS のメディアクエリか、Tailwind の `motion-safe:`・`motion-reduce:`) があることを確かめ、無ければ `ok: false` にする。結果に動きの点検の項目を足す
- LLM の生成では、動きの点検に通らなければ、CSP の点検と同じく 1 回だけやり直す
- 色の直書きの自動の点検は今回は足さない (LLM への指示にとどめる)

保存

- プロジェクトの形を版 3 にする。プロジェクトに表現を持たせ、保存した 1 件ごとに「何を作ったか (ページ / 部品帳 / 部品 / デザインガイド)」と「作ったときの表現」を持たせる。ページは今までどおり画面の種類の名前と当てた骨組みの種類を持ち、部品は部品の名前を持つ
- 版 2 は読むときに直す: 表現は `none` × `none`、今のページは「ページ」で表現 `none` × `none` の 1 件になる
- 部品帳を作り直したら上書きし、部品は名前ごとに別の 1 件にする。デザインガイドはプロジェクトの中の 1 つのフォルダにし、作り直したら置き換える

見本帳

- 見本帳に「表現」のタブを足す: (1) 面ごとの部品帳 (スタイルはミニマルに固定。Material・Glass・Solid・指定しない の 4 枚)、(2) 動きの見本 12 件が実際に動く一覧
- スタイル × 画面の種類 × 面 × 動きの全部の組み合わせは作らない
- 面ごとの部品帳は、ほかの見本と同じく、手順に沿って作ってリポジトリに置く生成物とする

作る順番

- 第 1 段 (style-guide のリポジトリ、別の PR): `render --seed` に文書のオプションを足す
- 第 2 段: 表現 (面の台帳・動きの見本集・表現の一覧・骨組みへの面の層・案とページへの反映・`check-page` の動きの点検・CSS の決まりの更新・保存の版 3・作業台の選択)
- 第 3 段: 部品帳と部品 (生成・作業台の「作るもの」・保存)
- 第 4 段: デザインガイド (台帳の ref を上げる・組み立て・古い style-guide のときの扱い)
- 第 5 段: 見本帳の「表現」のタブ

## Testing Decisions

良いテストは、外から見える振る舞いだけを確かめる。関数の中の途中経過や、LLM への指示の細かい文言や、画面の DOM の細かい形には縛られない。

合意済みの seam (テストを先に書く境界):

1. **サーバーの HTTP** (偽の claude CLI と偽の style-guide を差し込む):
   - 表現の一覧の API が、面 4 つと動きの見本 12 件を返す
   - 作るもの (ページ / 部品帳 / 部品 / デザインガイド) ごとに、殻と点検を通った HTML (とデザインガイドの文書) を返す
   - 表現と指定した動きの見本が、LLM の入力に入る (偽の claude CLI が受け取った入力で確かめる)
   - 表現を省いたページの生成が今までどおり動く
   - 動きの点検に通らない出力のとき、1 回やり直し、2 回とも通らなければエラーになる
   - 版 3 の保存と読み戻しが同じになる。版 2 のプロジェクトを読める。1 件ごとの種類と表現が残る
   - style-guide が古いとき、デザインガイドを頼むと部品帳だけを返し、更新の案内を返す
2. **CLI**:
   - 表現の一覧のサブコマンドが、面の台帳と動きの見本集を返す
   - `render-direction` に面を付けると、骨組みに面の CSS の層が入り、`check-page` を通る
   - `check-page` が、動きがあって reduced-motion の指定が無い HTML を `ok: false` にし、指定がある HTML (メディアクエリ・`motion-safe:`・`motion-reduce:` のどれでも) と動きの無い HTML を通す
   - デザインガイドのサブコマンドが、決まったファイルをフォルダに書く。style-guide が古いときは部品帳とテーマだけを書き、出力で知らせる
   - `project save` が、作るものの種類と表現を保存する
   - 動きの見本集の各見本の HTML が、殻に入れたとき `check-page` を通る
3. **style-guide の CLI** (style-guide のリポジトリ):
   - `render --seed` に文書のオプションを付けると、Seed ごとの `style-guide.md` の中身が決まった形で出る (同じ入力から同じ中身)
   - オプションを付けないときの出力が、今と変わらない
   - `--out` と一緒に付けると `style-guide.md` も書く

偽の claude CLI は、部品帳・部品の HTML と、トンマナ・部品の使い方の値にも答えられるように広げる。偽の style-guide は、文書のオプションに答える版と、知らない (古い) 版の両方を用意する。

画面は、今と同じく、作業台の本文を読んで、使う API のパス・`innerHTML` を使わないこと・プレビューの sandbox を確かめるテストにとどめる。

お手本にする既存のテスト:

- サーバー: サーバーのテスト (偽の LLM を `DESIGN_STUDIO_LLM_CMD` で、偽の style-guide を `STYLE_GUIDE_DIR` で差し込むもの)
- 骨組みと点検: 骨組みとページの CLI のテスト (`hasPageCsp` と `findDisallowedUrls` を当てるもの)
- 保存: プロジェクトの CLI のテスト
- style-guide: style-guide のリポジトリの `render` のテスト

## Out of Scope

- React・Vue などの部品のコードの書き出し。部品帳と部品は 1 ファイルの HTML だけ
- デザインガイドを zip などの 1 ファイルにまとめること。フォルダとして置くだけ
- Neumorphism・Brutalism・Clay などの面 (データを足せば増やせる形にはする)
- スクリプトで動かす動き (GSAP など)。動きは CSS だけ
- SVG フィルタの屈折を、既定の Glass の見た目にすること (Chromium だけの上乗せにとどめる)
- 骨組みに動きを入れること
- 見本帳での、スタイル × 画面の種類 × 面 × 動きの全部の組み合わせ
- 色の直書きの自動の点検
- トンマナを style-guide に作らせること (ADR 0005)
- 表現をパッドで混ぜること (ADR 0004)

- 用語は `CONTEXT.md` (表現・面・動き・動きの見本・部品・部品帳・トンマナ・デザインガイド) に合わせる。設計判断は ADR 0004 (表現は混ぜずに選ぶ) と ADR 0005 (デザインガイドの受け持ち) にある
