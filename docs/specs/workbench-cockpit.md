# 作業台のコックピット化 (案 4 つの編集・パッドで混ぜる・背景スケッチ)

## Problem Statement

作業台は、曖昧な一言を 1 つ書き、方向性の案を 3 つ見比べ、軸ごとに案を 1 つ選び、少しだけ調整してページを作る、縦に長い手順の画面になっている。利用者 (デザイナーでない人) からは、次の不満が出ている。

- 画面の種類が LP・ダッシュボード・ブログ記事の 3 つしかなく、作りたい画面 (料金ページ、設定画面など) を選べない
- 一言だけでは、作りたいもの・使う人・入れたい要素を伝えきれない
- AI が出した案に「惜しい」ところがあっても、案そのものを直せない
- 混ぜるときに「色は A と C の間くらい」のような度合いを選べず、案のどれか 1 つを選ぶしかない
- 手順が縦に並んでいるので、調整した結果をプレビューで確かめるのに上下に行き来する
- 決めた見た目を、ページ以外の形 (デザイントークン) で持ち出せない
- 最近よく見る「計算式で描いたジェネラティブな背景」のような、印象に残る装飾を足す手段がない

## Solution

作業台を、1 画面で「依頼を書く → 案を見比べて直す → 混ぜて微調整する → ページを作る」までを行き来できるコックピットに作り直す。

- 左に依頼のフォームと案の一覧、中央に端末を切り替えられるライブプレビュー、右に調整のパネル (パッド・スライダー・コントラスト・トークン) を並べる
- 画面の種類は、候補を 7 つに増やし (骨組みも足す)、自由な名前でも書けるドロップダウンにする。候補にない種類は、一番近い骨組みの種類でプレビューする
- 依頼はフォーム (作りたいもの・雰囲気・使う人・入れたい要素・スクリーンショット) で書く
- AI は方向性の案を 4 つ出す。利用者は案のどの項目も編集でき、AI の原案はいつでも戻せるように残る。出し直した回も履歴に残る
- 混ぜる軸 (色・フォント・形・配置) ごとのパッドで、4 案の間を点でドラッグして、混ぜる度合いまで選ぶ
- 混ぜた結果の上にスライダーで微調整を重ね、項目ごとに混ぜた値へ戻せる
- テーマを Tailwind・JSON・CSS 変数の 3 形式で書き出せる。コントラストの判定とチェックリストを見られる
- (第 2 段) 任意で、計算式で描く背景スケッチをテーマの色で付けられる。見本から選ぶ・自分で貼る・LLM に任せる、の 3 つから始められる。ページには止まった画像として焼き込まれる

## User Stories

依頼と画面の種類

1. 利用者として、画面の種類をドロップダウンの候補から選びたい。どんな画面を作れるかが分かるから
2. 利用者として、候補にない画面の種類を自由な名前で書きたい。自分の作りたい画面にぴったりの名前で頼めるから
3. 利用者として、候補に料金ページ・商品詳細・ポートフォリオ・設定画面があってほしい。よく作る画面を骨組み付きで見比べられるから
4. 利用者として、自由な名前で書いた画面の種類が、どの骨組みでプレビューされているかを知りたい。プレビューが作りたい画面と違って見えても戸惑わないから
5. 利用者として、自由な名前の画面の種類に当てられた骨組みの種類を選び直したい。AI の判断が外れていても直せるから
6. 利用者として、作りたいものを複数行で書きたい。一言では伝えきれない中身を伝えられるから
7. 利用者として、雰囲気・キーワードを任意で書きたい。見た目の好みを伝えられるから
8. 利用者として、誰が使うかを任意で書きたい。使う人に合った案が出るから
9. 利用者として、必ず入れたい要素を任意で書きたい。ページに入れ忘れが出ないから
10. 利用者として、今までどおりスクリーンショットを添えたい。言葉にしにくい見た目を伝えられるから
11. 利用者として、作りたいものを書かずに案を出そうとしたら、何が足りないかを教えてほしい。迷わずに直せるから

案と回

12. 利用者として、方向性の案を 4 つ見比べたい。選択肢が少なすぎず多すぎないから
13. 利用者として、案ごとに名前と狙いを読みたい。案の違いを言葉でも理解できるから
14. 利用者として、案の名前・狙い・文章を書き換えたい。AI の案の惜しいところを直せるから
15. 利用者として、案の色・形・フォント・配置を変えたい。見た目の惜しいところを直せるから
16. 利用者として、編集した案を AI の原案に戻したい。直しすぎても元に戻れるから
17. 利用者として、案が原案から編集されているかどうかをひと目で知りたい。どれを直したかを忘れないから
18. 利用者として、案を出し直したい。どの案もしっくりこないときにやり直せるから
19. 利用者として、出し直す前の回の案を呼び戻したい。前の回の案のほうが良かったと気付いたときに戻れるから
20. 利用者として、回の履歴を保存したプロジェクトでも見たい。あとで開き直しても、比べた経緯が残るから
21. 利用者として、案を出している間、進み具合を見たい。数十秒待つ間に不安にならないから
22. 利用者として、案を出すのに失敗したら、理由と再試行の手段を見たい。どうすればよいか分かるから

混ぜる・微調整

23. 利用者として、混ぜる軸ごとに 4 案の間で点をドラッグしたい。色は A 寄り、形は B と C の間、のように度合いまで選べるから
24. 利用者として、パッドの 4 隅にどの案があるかを見たい。ドラッグの向きが分かるから
25. 利用者として、点を動かすとプレビューがすぐ変わってほしい。度合いの違いを目で確かめられるから
26. 利用者として、フォントや配置がどの案のものになっているかを知りたい。この 2 つは混ざらず、どこかで切り替わるから
27. 利用者として、「この案で決める」で 4 つのパッドを一度にその案へそろえたい。1 つの案をそのまま使いたいときに速いから
28. 利用者として、最初は案 A がそのまま選ばれていてほしい。何もしなくてもプレビューが出るから
29. 利用者として、混ぜた結果の色相・彩度・アクセントの色相・角丸・余白・ライト/ダークをスライダーなどで微調整したい。最後のひと押しを自分で決められるから
30. 利用者として、微調整した項目だけを混ぜた値に戻したい。一部だけやり直せるから
31. 利用者として、微調整してもパッドや案が変わらないでほしい。混ぜ方を見直すときに、元の案が崩れていないから
32. 利用者として、ページの文章 (見出し・リード・項目) も微調整で直したい。混ぜた結果の文章が依頼とずれていても直せるから
33. 利用者として、スライダーを連打してもプレビューがちらつかないでほしい。落ち着いて調整できるから

プレビュー・コントラスト・トークン

34. 利用者として、プレビューをデスクトップ・タブレット・モバイルの幅で切り替えたい。端末ごとの見え方を確かめられるから
35. 利用者として、今のテーマのコントラストの判定 (AA / AAA) を見たい。読みにくい組み合わせに気付けるから
36. 利用者として、確かめるべきことのチェックリストを見たい。ページを作る前の見落としが減るから
37. 利用者として、テーマを Tailwind の `theme.css` として書き出したい。Tailwind のプロジェクトにそのまま入れられるから
38. 利用者として、テーマを JSON として書き出したい。ほかの道具に読ませられるから
39. 利用者として、テーマを素の CSS 変数として書き出したい。Tailwind を使わないプロジェクトでも使えるから

ページ・保存

40. 利用者として、混ぜて微調整した見た目と依頼をもとに、LLM にページを作らせたい。決めた見た目の完成品を得られるから
41. 利用者として、自由な名前の画面の種類で作ったページが、その名前の用途に合っていてほしい。骨組みの種類に引っ張られないから
42. 利用者として、画面の種類を変えて、同じ見た目で別のページも作りたい。サイト全体をそろえられるから
43. 利用者として、同じ骨組みに当たる 2 つの画面の種類 (例: 料金ページとプラン比較) のページを、別々に保存したい。片方がもう片方を上書きしないから
44. 利用者として、プロジェクトを保存し、依頼・回の履歴・パッドの位置・微調整・背景スケッチ・ページを開き直したい。続きから作業できるから
45. 利用者として、前の形で保存したプロジェクトも開きたい。作り直しの前の作業も無駄にならないから
46. 利用者として、幅の狭い画面でも作業台を使いたい。ノート PC の小さな画面でも作業できるから

背景スケッチ (第 2 段)

47. 利用者として、背景スケッチを付けるかどうかを選びたい。いらないページには付けずに済むから
48. 利用者として、同梱の見本のスケッチから選びたい。式を書けなくても背景を付けられるから
49. 利用者として、自分で見つけた式を貼りたい。気に入った表現を使えるから
50. 利用者として、方向性に合うスケッチを LLM に任せて作らせたい。自分で式を探さなくて済むから
51. 利用者として、スケッチが動く様子を作業台の中で見たい。どんな背景かが分かるから
52. 利用者として、スケッチがテーマの色で描かれてほしい。ページの見た目となじむから
53. 利用者として、テーマの色を変えたら背景スケッチの色も変わってほしい。調整のたびに付け直さなくて済むから
54. 利用者として、背景をヒーローだけに付けるか、ページ全体に付けるかを選びたい。ページに合った強さにできるから
55. 利用者として、背景を止めるか、ゆっくり動かすかを選びたい。落ち着いたページにも動きのあるページにもできるから
56. 利用者として、重すぎる・終わらない式を貼っても、作業台が固まらないでほしい。作業を失わないから
57. 利用者として、スケッチが動かないとき、理由 (使えない関数・時間切れ・エラー) を知りたい。式を直せるから
58. 利用者として、背景を変えたとき、ページを作り直さずに差し替えたい。数分待たずに済むから
59. 利用者として、背景を付けたページも、今までどおり安全な (外部へ通信しない) ページであってほしい。書き出したページを安心して使えるから
60. 利用者として、骨組みのプレビューでも、焼き込んだ背景を見たい。ページを作る前に背景との相性を確かめられるから

## Implementation Decisions

画面の種類と骨組み

- 骨組みの種類を 7 つにする: 今の LP・ダッシュボード・ブログ記事に、料金・商品詳細・ポートフォリオ・設定画面を足す。足す 4 つも配置の型を 3 つずつ持つ (骨組みは合わせて 12 枚増える)。見本帳の横軸も 7 つになる
- 画面の種類は「利用者に見せる名前」と「当てた骨組みの種類」の組で持つ。候補から選んだときは両方が決まる。自由な名前のときは、案を出す LLM の呼び出しの中で「一番近い骨組みの種類」も答えさせ、利用者が選び直せる
- ページを作る LLM には、利用者に見せる名前をそのまま渡す (骨組みの種類ではなく)
- ページの保存のキーは、画面の種類の名前から作った識別子 (英小文字・数字・ハイフン) にする。同じ骨組みに当たる 2 つの名前のページがぶつからないようにするため (設計者の判断。利用者とは未確認)

依頼

- 依頼は、作りたいもの (必須)・雰囲気とキーワード・使う人・入れたい要素 (いずれも任意)・スクリーンショット (任意、今までどおり png/jpeg 5MB まで) の組。方向性の案とページの両方の LLM の入力になる

案と回

- 方向性の案を出す API は、案を 4 つ (固定) と、自由な名前の画面の種類のときは当てた骨組みの種類を返す
- 回は、原案 4 つと、それぞれの編集後の案を持つ。原案は書き換えない。出し直すと新しい回を足し、前の回も残す
- 案の編集は、案のすべての項目 (名前・狙い・文章・テーマの種・配置) を対象にする。編集後の案は、サーバーの方向性の確かめを通す

混ぜる (ADR 0003)

- 混ぜる軸は今までどおり色・フォント・形・配置の 4 つ。軸ごとにパッドを 1 枚置き、4 隅に案を置く (案 A・B・C・D の位置は固定)
- 画面からは、軸ごとの点の位置 (0〜1 の x, y) を送る。重みはパッドの 4 隅に対する双一次の重みとし、計算はサーバーの混ぜる計算のモジュールだけで行う
- 連続に混ぜるもの: 色相 (主色・アクセント・無彩色。円周上の重み付き平均)、彩度、コントラスト、角丸、余白の倍率
- 吸着させるもの: ライト/ダークとテーマの雰囲気 (色の軸)、影の種類 (形の軸)、フォント (フォントの軸)、配置の型 (配置の軸)。その軸で一番重い案のものを使う。重みが同じなら A → B → C → D の順で先のもの
- アクセントの色相が無い案は、アクセントの色相の平均から外す。全員が無ければ、結果も無し
- ページの文章は、4 軸の重みの合計が一番大きい案から取る
- 混ぜた結果の id は、点の位置から決まる値にする (同じ位置なら同じ id)
- 最初の点は案 A の隅。「この案で決める」は 4 軸の点をその案の隅に置く

微調整

- 微調整は、混ぜた結果に重ねる上書きの組 (項目ごとに有無を持つ)。対象は、色相・彩度・アクセントの色相・コントラスト・角丸・余白・影・ライト/ダーク・フォントの組・配置の型・ページの文章
- 微調整は案もパッドの位置も変えない。項目ごとに外せる

プレビュー・コントラスト・トークン

- プレビューの幅は、デスクトップ 1280px・タブレット 768px・モバイル 375px の 3 つ
- コントラストの判定は、style-guide の `render --seed` が返す結果 (`checks`・`failed`) を使う。AA / AAA の表示と、チェックリスト (コントラストの基準・日本語フォントの読み込み・モバイルでの見え方を確かめたか) を出す
- トークンの書き出しは、Tailwind (style-guide の `theme.css` そのまま)・JSON (`theme.json`)・CSS (`theme.css` から、Tailwind の書き方を除いて `:root` などの CSS 変数だけにしたもの) の 3 形式。サーバーに書き出しの API を足す

画面

- 作業台を 3 列にする: 左が依頼のフォームと案の一覧 (回の切り替え・編集・原案に戻す)、中央がライブプレビュー (端末の切り替え・ページの表示)、右が調整のパネル (パッド 4 枚・微調整・コントラスト・トークン・背景スケッチ)
- 幅 1280px 以上を前提にし、それより狭いときは右のパネルを中央の下に回す
- 台帳・見本帳のタブは変えない
- 今の作業台の決まりは引き継ぐ: API の値は `innerHTML` に入れない。プレビューの iframe は `sandbox="allow-scripts"` だけ。古い応答は作業の世代で捨てる。連打は 300ms ほど待ってから送る

保存

- プロジェクトの保存の形式に版の番号を足す。新しい形は、依頼・回の履歴・パッドの点・微調整・背景スケッチ・画面の種類ごとのページ (名前と当てた骨組みの種類つき) を持つ
- 古い形 (版の番号が無いもの) は、読むときに新しい形へ直す: 一言 → 作りたいもの、方向性 1 つ → 原案 1 つだけの回、案の添字の組 → その案の隅の点

背景スケッチ (第 2 段、ADR 0002)

- スケッチは p5.js 風の書き方。p5.js 本体は読み込まず、よく使う関数 (キャンバスの作成・背景・線の色と太さ・点・線・三角関数・`mag`・`PI` など) だけを自前で用意する。無い関数はエラーで知らせる
- スケッチは作業台の中の sandbox の iframe (allow-scripts だけ) にある Worker で、OffscreenCanvas に描く。1 フレームが 2 秒を超えたら Worker を止めて時間切れとして知らせる
- 色付け: 描いた絵の明るさを、テーマのグラデーション (背景色 → 主色 → アクセント色) に置き換える。スケッチが色を指定していれば、その色を使う
- 焼き込み: WebP の 1600×900、300KB 以内を目安にする。超えたら画質を下げ、それでも超えたら大きさを下げる
- ページへの差し込み: ページを作る LLM に、ヒーローの区画へ目印の属性を付けさせる。アプリは CSP の meta のあとに、目印 (無ければページ全体) へ背景の画像を当てる `<style>` を差し込む。差し込んだあとも、ページの確かめ (CSP の meta の位置と、許可していない URL が無いこと) を通る。背景を変えたら差し込み直すだけにする
- 動き: 既定は止まった画像。選べば CSS のアニメーションでゆっくり動かす
- 骨組みのプレビューにも、焼き込んだ画像を出す。動く様子は、背景スケッチの編集パネルの小さなライブプレビューだけで見せる
- 背景スケッチはプロジェクトに 1 つまで。色は、その時点の混ぜた結果 + 微調整のテーマに追従する
- 入手先は 3 つ: 同梱の見本 (新しく書いたもの 4〜6 個だけ。作者の許可が分からない式は同梱しない)、利用者が貼る、LLM に任せる。LLM に任せるときは、方向性の名前と雰囲気・依頼の雰囲気を渡し、使える関数を自前の一覧に限る。返ってきた式を sandbox で 1 フレーム試し、エラーか時間切れならエラーを添えて 1 回だけ書き直させる。それでもだめなら見本を勧める

作る順番

- 第 1 段: 画面の種類と骨組み、依頼のフォーム、案 4 つと回の履歴と編集、パッドで混ぜる、微調整、端末の切り替え、コントラスト、トークン、保存の形式
- 第 2 段: 背景スケッチ

## Testing Decisions

良いテストは、外から見える振る舞いだけを確かめる。関数の中の途中経過や、画面の DOM の細かい形には縛られない。

合意済みの seam (テストを先に書く境界):

1. **混ぜる計算**: パッドの点 → 4 案の重み (隅・辺・中央)、色相の円周平均 (350° と 10° → 0°)、吸着 (同じ重みのときの順番を含む)、アクセントの色相が無い案の扱い、同じ点なら同じ id
2. **画面の種類**: 候補の 7 つと自由な名前、当てた骨組みの種類、骨組みの 21 枚 (7 種類 × 3 型) がどれも描ける
3. **スケッチの自前の関数**: 決まった `t` とキャンバスの大きさで、同じ点の列が出る (貼ってもらった種類の式が動く)。無い関数はエラーになる
4. **色付けと焼き込み**: 明るさ → テーマのグラデーション、画像の大きさの上限 (画質 → 大きさの順に下げる)
5. **ページへの差し込み**: 差し込んだページが、ページの確かめ (CSP の meta の位置・許可していない URL) を通る。目印の無いページにも入る。差し込み直しで背景が 2 重にならない
6. **保存**: 古い形のプロジェクトを読める。新しい形を保存して読み戻すと同じになる。同じ骨組みに当たる 2 つの画面の種類のページが別々に保存される
7. **サーバーの API**: 案を出す API が 4 案と当てた骨組みの種類を返す (偽の LLM で)。混ぜる API が点の位置を受け取る。トークンの書き出しが 3 形式を返す

画面は、今と同じく、作業台の本文を読んで、使う API のパス・`innerHTML` を使わないこと・プレビューの sandbox を確かめるテストにとどめる。

お手本にする既存のテスト:

- 混ぜる計算・骨組み: 方向性と骨組みの CLI のテスト (`scripts/` の direction・skeletons-* のテスト)
- ページの確かめ: ページの CLI のテスト (`hasPageCsp` と `findDisallowedUrls` を当てるもの)
- 保存: プロジェクトの CLI のテスト
- API: サーバーのテスト (偽の LLM `app/mock-llm.mjs` を `DESIGN_STUDIO_LLM_CMD` で差し込む)
- 画面: 作業台の本文を読むテスト
