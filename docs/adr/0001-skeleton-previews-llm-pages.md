# 方向性の案は骨組みで描き、ページは LLM で作る。テーマの種からの CSS 作成は style-guide の CLI に足す

方向性の案を LLM に毎回自由な HTML で描かせると、案を 3 つ出すたびに数分かかり、案どうしの差がテーマのせいか配置のせいかも見分けにくい。そこで、案は画面の種類 × 配置の型ごとの固定の骨組みにテーマを流し込んで描き、速さ・比べやすさ・混ぜやすさを優先する。自由度の高さは、決まった方向性を条件に LLM が作るページで出す。骨組みにテーマを流し込むには「テーマの種 → theme.css」が要るが、style-guide の CLI にはこの入口が無い。内部モジュールを直接読み込む案と、推定結果を組み立てて `run` に渡す案もあったが、前者は style-guide の中身に縛られ、後者は混ぜた結果を正確に表せない。そのため style-guide に `render --seed` を足し、両者の約束事を CLI の入出力だけに保つ。

## Consequences

- design-studio は、`render --seed` を持つ style-guide のコミット以降を前提にする。台帳の取得元に、そのコミットを固定する。
- 骨組みは完成品ではない。骨組みの見た目を磨き込む作業は、優先しない。
